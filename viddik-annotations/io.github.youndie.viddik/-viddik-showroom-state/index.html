ViddikShowroomState

class ViddikShowroomState

What the showroom is currently showing: the search query, and the component whose detail view is open (null while the list is).

Hoisted out of ViddikShowroom so a host can both read and drive it. The reason is the Android system back gesture: it has to close the detail view rather than the activity, and the only thing that can answer it is an androidx.activity.compose.BackHandler in the host. viddik-annotations deliberately does not depend on AndroidX to provide that itself — activity 1.11 brings the KMP androidx.lifecycle/savedstate artifacts, whose klibs collide by unique_name with the org.jetbrains.androidx forks Compose Multiplatform ships, and this module has native targets.

val state = rememberViddikShowroomState()
BackHandler(enabled = state.selected != null) { state.selected = null }
ViddikShowroom(components, state = state)
